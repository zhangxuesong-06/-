### 原始需求复述

> 规划一款本地代理启动器软件：启动时自动扫描本机已安装的 agent 软件（如 DeepSeek Harness、OpenCode 等），列出可选项供用户选择，并支持用户针对所选软件配置并启动本地代理。

### 本机实测事实（需求依据，不可推翻）

以下为 Windows 11 实测结论，直接决定产品形态：

| # | 事实 | 对产品的强制性含义 |
|---|---|---|
| F1 | 注册表 `HKLM/HKCU\SOFTWARE\...\Uninstall\*` 可稳定读到 DisplayName / DisplayVersion / InstallLocation，实测命中 DSH 0.2.1-rc.5、OpenCode 2.2.5、ZCode 3.14.3、MiniMax Code 3.0.57、WorkBuddy 5.9.3、Ollama 0.34.3、LM Studio 0.3.13 | 注册表是**主发现源**，但不是唯一源 |
| F2 | OpenCode / ZCode / MiniMax 的 InstallLocation 为空，真实路径须从进程路径反查（`%LOCALAPPDATA%\Programs\ai.opencode.desktop\OpenCode.exe`） | 必须「注册表 + 进程 + 约定目录」三源合并，单源不可用 |
| F3 | Electron 应用起多个同名进程（OpenCode 8 个、DSH 5 个） | 识别主键**必须是 exe 绝对路径**，不能按进程名 |
| F4 | CLI 版本号嵌在路径里（`%APPDATA%\ai.opencode.desktop\cli\22.2.5-x64\opencode-cli.exe`） | 版本号有多个来源（注册表 / 路径 / 进程），需标注来源与可信度 |
| F5 | 配置目录分散且 dotfile 风格：`~/.dsh/`、`~/.config/opencode/service.json`、`~/.claude/settings.json`、`~/.codex/.codex-global-state.json`、`~/.minimax/config.yaml`、`~/.zcode/` | 配置定位是**逐软件适配**工作，无法通用化 |
| F6 | `~/.dsh/settings.yaml` 中 provider 为 `baseURL: https://sekirocloud.shop/v1` + `apiKeyEnv: DSH_API_KEY` + `api: openai-completions` | 代理必须做**协议感知的 baseURL 改写**，纯 TCP 转发无价值；且需保证子进程能拿到 `DSH_API_KEY` 环境变量 |
| F7 | DSH 子进程实测监听 3082 | 存在可被嗅探/代理的本地 HTTP 服务面；也意味着端口可能已被占用 |
| F8 | 本机装有 `cc-switch`，settings 内已有 `enableLocalProxy`、`showProfileSwitcher`、`visibleApps{claude,codex,gemini,opencode...}` | 存在直接竞品，且已做到「多 agent 配置切换 + 本地代理」的一部分 |

### 补充实测事实（本次核对新增，风险章节的一手依据）

| # | 事实 | 含义 |
|---|---|---|
| F9 | `~/.config/opencode/service.json` 内容为 `{"password": "<明文>"}` | 本机已存在明文凭据文件，代理读取配置即触碰密钥 |
| F10 | `~/.claude/settings.json` 中 `ANTHROPIC_AUTH_TOKEN` 为明文 key，且 `ANTHROPIC_BASE_URL` 已被手改为第三方 `api.deepseek.com/anthropic` | 「改 baseURL 指向代理」模式用户已在手动实践 → 需求真实存在；但用户已习惯明文凭据 |
| F11 | `~/.dsh/settings.yaml` **实际不存在**，已被重命名为 `settings.yaml.imported` | 上游会在导入/升级后**改名或迁移配置文件**，写死路径的适配必然失效 |
| F12 | `~/.dsh/dsh-bridge/config.json` 含 PBKDF2 密码哈希、`secretToken`、`allowLoopback: true`、cloudflared 隧道配置，以及 **QQ appSecret 明文** | 隧道叠加本地代理 = 可能把服务推到公网 |
| F13 | 实测 `0.0.0.0:3082`（DSH 端口）绑定在**全网卡**而非 127.0.0.1；同时 7897（系统代理）、8080、3580/3582 等端口已占用 | 本地服务默认已暴露到局域网；端口冲突是常态而非例外 |

## 1. 产品定位与目标用户

### 1.1 一句话价值主张

> **一键发现本机所有 agent 软件，为选中的那一个挂上本地代理，改坏了还能一键还原。**

### 1.2 解决什么痛点

| 痛点 | 现状（实测） | 产品后价值 |
|---|---|---|
| 不知道自己装了哪些 agent | 装了就忘，靠翻开始菜单 | 启动页自动列出全部已装 agent 及其版本与运行态 |
| 想接本地代理要手改配置 | 用户已手动把 `ANTHROPIC_BASE_URL` 改成第三方地址（F10） | 界面上填一次上游地址，自动落到正确配置字段 |
| 改配置怕改坏、改完忘了原值 | 无备份机制，`settings.yaml` 已被改名成 `.imported`（F11） | 改写前自动备份，一键回滚，可查看 diff |
| 每个软件配置位置和格式都不同 | `.dsh/settings.yaml`(YAML) / `service.json`(JSON) / `config.yaml` 各不相同 | 内置适配器，用户不需要知道文件在哪 |
| 端口不知道有没有被占 | 3082/7897/8080 已被占用（F13） | 启动前预检，冲突时给建议端口 |

### 1.3 目标用户

| 画像 | 描述 | 核心诉求 | 优先级 |
|---|---|---|---|
| P-A 多 agent 并行使用者 | 同时装 5+ 个 agent 客户端（实测本机已装 7 个），试新工具是常态 | 一份清单看清全部，快速切换 | 主目标 |
| P-B 自建模型网关的开发者 | 有自建/第三方 OpenAI 兼容端点，想统一接管各 agent 的模型调用 | 一次配置，多软件复用上游地址 | 主目标 |
| P-C 排障与审计需求者 | 想看 agent 到底把请求发去哪、发了什么 | 运行态面板 + 请求元数据日志 | 次目标 |
| P-D 只想看不想改的谨慎用户 | 怕改坏环境，只要「探测」 | 只读模式 | 次目标（决定 Q3） |

### 1.4 产品目标（3 个正交目标）

1. **发现要准**：本机已装 agent 的识别覆盖率 ≥ 90%，同一软件不出现重复条目，识别不出的可手动指路径。
2. **代理要能用**：对至少 1 个软件（P0 建议 DeepSeek Harness）完成「配 → 启 → 通 → 停 → 还原」全链路闭环。
3. **改坏能兜底**：任何配置改写 100% 有备份、可一键还原，失败不留下半损坏状态。

## 2. 竞争与替代方案

| 方案 | 优势 | 劣势（实测依据） | 本产品态度 |
|---|---|---|---|
| **cc-switch**（已装，F8） | 已实现配置切换 + `enableLocalProxy` 开关；有托盘、技能同步、多 app 视图 | `visibleApps` 仅覆盖 claude / codex / gemini / opencode 等，**未覆盖 DeepSeek Harness / MiniMax / ZCode**；`enableLocalProxy` 默认关；定位是「供应商配置切换器」，不做「发现 + 启动 + 回滚」闭环 | **主要竞品**。不在「切换供应商」上正面竞争，补它的覆盖盲区与全链路 |
| 手改 config 文件 | 零成本、完全可控 | 需知道每个软件的路径与 schema；改坏无备份（F11 已证明文件会被改名） | 本产品要把这件事变成一次点击 |
| 环境变量 / 系统代理（如 7897） | 通用、对所有程序生效 | 只影响走系统代理的流量；无法改写 `baseURL`；会代理全部流量，副作用大；与本地代理叠加易成环路（F13） | 不替代它，但要**检测并避开** |
| 各 agent 客户端自带 proxy / 自定义 baseURL | 官方支持、最稳 | 每个软件配一遍，格式各异；版本升级后可能重置 | 本产品是「批量配置器 + 保险丝」，不是替代它们 |
| 抓包工具（Charles/Fiddler/mitmproxy） | 能力强、通用 | 面向调试不面向使用；需装证书；对 Electron 应用配置麻烦；无回滚 | 不做同类，只借鉴运行态面板的信息呈现 |

### 差异化定位

**做**：本机 agent 的**发现 → 选择 → 适配配置 → 预检 → 启动 → 运行态 → 一键还原**这一条链路，覆盖 cc-switch 未覆盖的软件。

**明确不做（Out of Scope 摘要，详见 §5.3）**：

| 不做 | 原因 |
|---|---|
| 云端账号体系 / 用量计费 / 模型路由计费 | 需要服务端与合规资质，且与「本地工具」定位冲突 |
| 逆向破解、绕过客户端的授权校验 | 法律与 ToS 红线 |
| 通用透明 TCP 代理 / 全局流量劫持 | 需求本质是「改 baseURL」（F6），纯转发无价值且风险大 |
| 替代 cc-switch 的供应商切换 / 多账号管理 | 竞品已成熟，正面竞争无胜算 |
| 代理内容的语义分析、prompt 改写、内容审核 | 高危且无需求支撑 |
| P0 阶段的多软件并发代理 | 单实例已能验证核心价值，见 Q4 |

## 3. 用户故事

| # | 作为 | 我希望 | 以便 | 验收要点 |
|---|---|---|---|---|
| US-01 | 新用户 | 首次启动时自动扫描并列出本机所有 agent，显示名称/版本/路径/运行状态 | 不用自己翻开始菜单找装了啥 | 首屏 ≤5s 出列表；实测 7 个软件中至少命中 6 个 |
| US-02 | 用户 | 当某软件注册表没有 InstallLocation 时，程序自己从进程路径或约定目录找到它 | 不会因为"路径为空"就显示未安装 | OpenCode/ZCode/MiniMax 能显示真实 exe 路径（F2） |
| US-03 | 用户 | 同一个软件只显示一条，不因 Electron 多进程重复 | 列表不刷屏 | OpenCode 8 进程只出 1 条（F3） |
| US-04 | 用户 | 手动指定某个软件的可执行文件路径并被记住 | 自动识别失败时还能用 | 手动路径重启后仍保留 |
| US-05 | 用户 | 选择软件后看到它的当前代理配置（上游地址、API 协议、鉴权方式）原值 | 知道现状再决定改不改 | 显示 `baseURL` / `api` / `apiKeyEnv` 原值（F6） |
| US-06 | 用户 | 填上游地址和本地监听端口后，一键写进该软件的配置 | 不用自己找文件、查 schema | 写后配置文件字段值正确，格式未被破坏 |
| US-07 | 用户 | 启动前被告知端口被占用/配置文件不可写，而不是启动后才失败 | 快速定位问题 | 占用 3082 时给出冲突提示 + 建议端口（F13） |
| US-08 | 用户 | 点启动后能实时看到请求数、错误率、最近请求的目标地址 | 判断代理是否真的在工作 | 运行态 1s 内刷新，无 body 明文 |
| US-09 | 用户 | 停止代理后配置自动还原成原值 | 不把环境留在半改状态 | 停止后配置 diff 为空 |
| US-10 | 用户 | 代理异常退出时提示「配置仍是改写状态」并提供还原按钮 | 不会在不知情的情况下连不上模型 | 异常退出后启动页有醒目提示 |
| US-11 | 谨慎用户 | 只用只读模式扫描与查看，不写任何文件 | 在不信任的情况下也能用 | 只读模式全程零写入（文件 mtime 不变） |
| US-12 | 用户 | 上游软件升级导致配置结构变了时，程序提示「配置不识别」而不是乱写 | 不会把新版配置写坏 | 未知 schema 时拒绝写入并降级只读（F11 场景） |
| US-13 | 排障用户 | 一键打开备份目录看到历史版本和还原点 | 出问题能自己回退 | 备份文件可见、可手动复制 |

## 4. 交互流程

### 4.1 主流程图

```mermaid
flowchart TD
    A[启动应用] --> B[自动扫描<br/>注册表 + 进程 + 约定目录]
    B --> C{扫描有结果?}
    C -- 否 --> C1[空状态页<br/>出口: 手动添加路径 / 重扫 / 查看扫描日志]
    C -- 是 --> D[列表呈现<br/>按 exe 绝对路径去重]
    D --> E{状态徽标}
    E --> E1[未安装]
    E --> E2[已安装未运行]
    E --> E3[运行中]
    E --> E4[端口占用]
    E --> E5[版本过低]
    E --> E6[配置不识别]
    D --> F[选择软件]
    F --> G[代理配置页<br/>监听地址 / 端口 / 上游地址 / 协议 / 鉴权 / 是否改写配置]
    G --> H{预检}
    H -- 端口被占用 --> H1[红色提示<br/>出口: 换端口 / 终止占用进程(需确认) / 取消]
    H -- 配置不可写 --> H2[黄色提示<br/>出口: 以只读模式继续 / 提权重试(可选) / 取消]
    H -- schema 不识别 --> H3[阻断写入<br/>出口: 仅查看 / 手动指定字段(高阶) / 取消]
    H -- 上游不可达 --> H4[告警<br/>出口: 仍启动(空转) / 改地址 / 取消]
    H -- 全部通过 --> I[写入配置<br/>自动备份为 .bak]
    I --> J[启动代理进程]
    J --> K{启动结果}
    K -- 失败 --> K1[回滚配置<br/>显示错误码与日志位置]
    K -- 成功 --> L[运行态面板<br/>QPS / 错误率 / 最近请求 / 日志尾]
    L --> M[停止]
    M --> N[停止代理 + 还原配置 + 校验 diff]
    N --> O[回到列表, 徽标恢复为已安装未运行]
    L --> P[异常退出]
    P --> Q[横幅告警: 配置仍为改写状态<br/>出口: 一键还原 / 查看日志]
```

### 4.2 各步骤的用户可见反馈与失败出口

| 步骤 | 用户可见反馈 | 失败出口 |
|---|---|---|
| 1. 启动 | 扫描进度条 + 已发现 N 个 | 扫描超时 → 展示部分结果 + 重扫 |
| 2. 扫描 | 分源展示「注册表命中 X / 进程命中 Y / 目录命中 Z」，可展开看来源 | 权限不足 → 提示以普通权限可用，缺失项标灰 |
| 3. 列表 | 每行：图标、名称、版本（标注来源）、路径、状态徽标 | 识别不全 → 行尾「纠正路径」入口 |
| 4. 选择 | 右侧详情抽屉，含配置位置与当前值 | 配置不存在 → 提示「未找到配置文件，可能尚未初始化」+ 引导先运行一次该软件 |
| 5. 代理配置 | 表单 + 实时生成的「将要写入的内容」预览（只读高亮 diff） | 用户不填 → 默认值预填（监听 127.0.0.1、端口自动挑空闲） |
| 6. 预检 | 4 项检查清单逐项打勾/打叉（端口、可写、schema、上游连通） | 见流程图 H1–H4，每项均可单独绕过或取消 |
| 7. 启动 | 配置备份路径提示 + 启动中态 | 启动失败 → 自动回滚 + 错误码 + 打开日志目录 |
| 8. 运行态 | QPS、错误率、最近 20 条请求（时间/目标/状态码/耗时）、日志尾 | 面板无数据 → 提示「无流量，检查软件是否已重启生效」 |
| 9. 停止 | 还原中 → 还原完成 + diff 校验结果 | 还原失败 → 保留备份路径 + 提供手动还原指引 |
| 10. 异常恢复 | 顶部横幅「配置仍为改写状态」 | 一键还原 / 忽略但保持横幅 |

### 4.3 状态徽标定义

| 徽标 | 判定条件 | 可执行动作 |
|---|---|---|
| 未安装 | 三源均未命中 | 手动指定路径 |
| 已安装未运行 | 找到 exe 且无对应进程 | 配置 + 启动 |
| 运行中 | 存在该 exe 绝对路径的进程 | 配置 + 重启生效提示 |
| 端口占用 | 目标端口已被其他进程 LISTEN | 换端口 / 结束占用进程（二次确认） |
| 版本过低 | 版本 < 适配器最低支持版本 | 查看要求 / 仍以只读模式使用 |
| 配置不识别 | 配置文件存在但 schema 未匹配 | 只读查看 / 提交诊断（导出脱敏配置结构） |

## 5. 功能范围

### 5.1 P0（Must have — 须在 1 个里程碑内交付）

| ID | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| P0-1 | 三源扫描 | 注册表 Uninstall + 进程枚举 + 约定目录，结果合并 | 实测 7 个软件命中 ≥6；OpenCode/ZCode/MiniMax 能拿到真实 exe 路径 |
| P0-2 | 按 exe 绝对路径去重 | 以绝对路径为唯一主键 | OpenCode 8 进程 → 1 条；DSH 5 进程 → 1 条 |
| P0-3 | 列表与状态徽标 | 6 种徽标（见 4.3） | 状态与真实进程/端口状态一致 |
| P0-4 | 手动指定路径 + 持久化 | 识别失败的手动兜底 | 重启后保留 |
| P0-5 | 单软件适配器（首发 DSH） | 定位 `~/.dsh/settings.yaml`、解析 provider、改 `baseURL` | 改写后 DSH 请求确实打到本地代理 |
| P0-6 | 代理配置表单 | 监听地址（默认 127.0.0.1）、端口（自动挑空闲）、上游地址、协议类型、鉴权方式、是否改写配置 | 表单值能正确落到配置字段 |
| P0-7 | 写前备份 + 原子写 + schema 校验 | `.bak` + 临时文件替换 + 写前结构校验 | 写坏可一键还原；非法规格拒绝写入 |
| P0-8 | 四项预检 | 端口占用、配置可写、schema 匹配、上游连通 | 占用 3082 时正确报冲突 |
| P0-9 | 本地 HTTP 反向代理 | 按 baseURL 转发到真实上游，注入鉴权头，env 变量透传（`DSH_API_KEY`） | 代理链路通；停止后软件能恢复直连 |
| P0-10 | 运行态面板 | QPS、错误率、最近请求元数据、日志尾 | 1s 刷新；**不记录 request/response body** |
| P0-11 | 停止 + 配置还原 + diff 校验 | 还原到备份，校验一致性 | 停止后 diff 为空 |
| P0-12 | 异常退出保护 | 代理崩溃时横幅告警 + 一键还原 | 强杀进程后重启能提示未还原状态 |
| P0-13 | 明文凭据不落盘 | 密钥仅在内存中继，日志脱敏 | 日志与自身配置文件中无明文 key |

### 5.2 P1 / P2

| ID | 优先级 | 功能 | 理由 |
|---|---|---|---|
| P1-1 | P1 | 扩展适配器：OpenCode、Claude Code(`~/.claude/settings.json`)、MiniMax、ZCode、Codex | 覆盖面决定产品价值，但需逐软件验证 |

### 5.3 Out of Scope（明确不做）

| 项 | 不做的理由 |
|---|---|
| 云端账号体系、登录、订阅 | 与本地工具定位冲突，需服务端与合规投入 |
| 模型路由计费、用量账单、token 计量结算 | 属商业系统范畴，非本产品目标 |
| 逆向破解、Patch 客户端、绕过授权校验 | 法律与 ToS 红线，直接排除 |
| 通用透明 TCP 代理 / 全局流量劫持 / 系统代理接管 | 需求是 baseURL 改写（F6），非必要且副作用大 |

| 直接托管用户的 API Key / 提供密钥托管服务 | 承担不必要的安全与法律义务 |

## 6. 风险与限制

### 6.1 技术风险

| ID | 风险 | 触发条件 | 影响 | 缓解措施 | 可验收项 |
|---|---|---|---|---|---|
| T1 | 软件识别不出或路径错误 | 注册表 InstallLocation 为空（实测 OpenCode/ZCode/MiniMax） | 列表显示"未安装"，用户以为没装 | 三源合并 + 进程路径反查 + 手动指定 + 记忆上次路径 | 该 3 款软件均能显示真实 exe 路径 |
| T2 | 同一软件重复出现 / 误杀进程 | Electron 多进程同名（OpenCode 8 个） | 列表刷屏；结束进程时误伤主进程 | 一律按 exe 绝对路径去重；进程操作前展示完整路径与 PID | 8 进程只出 1 条；进程操作弹窗显示 PID 列表 |
| T3 | 端口冲突导致启动失败 | 目标端口已被占用（实测 3082/7897/8080/3580 已占） | 启动直接失败，用户不知所措 | 启动前 bind 探测 + 自动挑空闲端口 + 冲突时列出占用进程并给建议端口 | 3082 被占时给出明确提示且能一键换端口 |
| T4 | 配置写坏导致软件不可用 | 写入过程中断、schema 理解错误、并发写入 | 用户的 agent 直接连不上模型 | `.bak` 备份 + 临时文件原子替换 + 写前 schema 校验 + 写后回读校验 + 一键还原 | 强杀写进程后配置文件仍可解析；还原后 diff 为空 |
| T5 | 上游升级导致适配失效 | 配置文件被改名/迁移（实测 `settings.yaml` → `settings.yaml.imported`）、字段改名 | 代理无法生效，可能写错字段 | 适配器版本化 + 多候选路径探测 + 未知 schema 时**拒绝写入**并降级只读 | 遇到 `settings.yaml` 缺失时显示"配置不识别"而非报错崩溃 |
| T6 | 版本判断错误 | 版本号来源不一（注册表 DisplayVersion vs 路径 `22.2.5-x64`） | "版本过低"误报，功能被错误阻断 | 多源版本比对 + 标注来源与可信度 + 冲突时以注册表为准并提示 | 版本展示带来源标注；冲突有提示 |
| T7 | 环境变量缺失导致鉴权失败 | 配置用 `apiKeyEnv: DSH_API_KEY`（F6），子进程环境无该变量 | 代理通了但上游 401 | 启动前检查所需 env 存在性 + 缺失时明确告知变量名（不显示值） | 缺 `DSH_API_KEY` 时提示变量名而非静默失败 |

### 6.2 安全风险

| ID | 风险 | 触发条件 | 影响 | 缓解措施 | 可验收项 |
|---|---|---|---|---|---|
| S1 | 明文凭据泄露 | 本机已有明文密钥：`~/.config/opencode/service.json` 的 `password`、`~/.claude/settings.json` 的 `ANTHROPIC_AUTH_TOKEN`、dsh-bridge 的 QQ `appSecret`（F9/F10/F12） | 密钥外泄，账号与额度被盗 | 只读取必要字段、内存中继不落盘、日志全量脱敏、自身配置文件加密或引用系统凭据库 | 抓日志与自身配置文件搜不到明文 key |
| S2 | 监听在 0.0.0.0 被局域网访问 | 用户手填 0.0.0.0，或继承上游习惯（实测 3082 就是 0.0.0.0，F13） | 同网段任何人可白用你的代理与密钥 | 默认且推荐 127.0.0.1；选 0.0.0.0 需二次确认并显示风险文案；首次可强制禁止 | 填 0.0.0.0 时必须二次确认 |
| S3 | 代理 + 隧道叠加暴露公网 | 同机运行 cloudflared 等隧道（F12 有 cloudflared 配置） | 本地代理被映射到公网，风险指数级上升 | 启动前检测隧道类进程并强告警；此状态下禁止 0.0.0.0 | 检测到 cloudflared 时弹出阻断性提示 |
| S4 | 中间人导致内容暴露 | 代理必然经手全部 prompt/response | 对话内容可被本工具或本机其他程序读取 | 默认**不记录 body**，仅元数据；日志本地且可一键清除；明示"本工具会看到你的请求内容" | 日志目录中无任何对话内容 |
| S5 | 代理嵌套 / 环回 | 本机已有系统代理 7897（F13），上游若指向它或指向自身 | 请求死循环、全部超时 | 上游地址校验：禁止指向自身监听端口；检测同机系统代理并提示可能双重代理 | 上游=自身端口时阻断并提示 |
| S6 | 提权后放大风险 | 配置在受保护目录需管理员权限 | 高权限进程持有用户密钥 | 默认不提权；确需提权时单独说明并最小化操作范围 | 提权操作有独立确认弹窗 |

### 6.3 合规与 ToS 风险

| ID | 风险 | 触发条件 | 影响 | 缓解措施 | 可验收项 |
|---|---|---|---|---|---|
| C1 | 改写第三方配置文件违反其许可/使用条款 | 对未声明支持外部改配置的软件写入（如 `~/.claude/settings.json`） | 法律风险 + 软件方不支持 | 默认**只读模式**；改写前必须用户显式勾选同意并展示"将修改哪个文件"；提供一键还原；适配清单标注每款软件的改写风险等级 | 首次改写前必有明确同意步骤；可查完整改写记录 |
| C2 | 代理转发触及上游服务条款（多账号/共享/转售） | 用户把他人 key 或共享 key 接入并转发 | 账号封禁 | 产品定位明确"单用户本机自用"；不做多账号轮转、不做 key 池、不做共享 | 产品内无 key 池/轮转能力 |
| C3 | 密钥注入方式触碰条款 | 从环境变量取出密钥再注入代理 | 争议 | 仅做本机透传，不改变密钥归属、不外发、不缓存 | 代码层面无外发密钥路径 |

### 6.4 产品风险

| ID | 风险 | 触发条件 | 影响 | 缓解措施 | 可验收项 |
|---|---|---|---|---|---|
| D1 | 上游软件版本升级导致适配大面积失效 | 客户端改配置结构（F11 已发生） | 核心功能失效，用户流失 | 适配器版本化 + 未知 schema 降级只读 + 内置"适配状态"页显示各软件支持等级 | 每款软件显示"已适配/仅只读/不识别" |
| D2 | 竞品 cc-switch 已内置同类能力 | cc-switch 开启 `enableLocalProxy` 并扩大 `visibleApps`（F8） | 被功能覆盖，无差异化 | 聚焦其未覆盖的软件（DSH/MiniMax/ZCode）+ 全链路闭环（发现→启动→回滚） | P0 覆盖软件在 cc-switch 中无对应支持 |
| D3 | 用户不信任代理工具 | 代理会碰密钥与对话内容 | 无人使用 | 只读模式 + 零 body 记录 + 开放审计（源码或可验证日志）+ 透明说明 | 只读模式实测零文件写入 |
| D4 | 用户觉得"我直接改 config 就行" | 只装 1–2 个软件的用户 | 价值不明显 | 定位多软件用户（实测本机 7 个）；单软件场景主打"备份与回滚" | 首屏即体现软件数量与配置分散度 |
| D5 | 适配维护成本随软件数量线性增长 | 每加一个软件需逆向其配置格式 | 团队被拖死 | 适配清单分等级（官方支持 / 社区贡献 / 实验性）；P1 才扩展 | 每个适配器有明确维护等级标注 |

> 合计 20 条风险，均含「触发条件 + 影响 + 缓解措施 + 可验收项」，可直接转为测试用例。
