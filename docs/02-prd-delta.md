## 1. 方向修正对照表

| 维度 | 旧理解（v1，已废弃） | 正确需求（v2） |
|---|---|---|
| 数据流向 | 代理挡在 agent **前面**：agent 的 `baseURL` 改成 `127.0.0.1:port`，请求经代理转发到云端上游 | 代理站在 agent **后面**：agent 是上游能力源，代理把它的模型能力在 `127.0.0.1:port` 暴露成端点，供下游 consumer 调用 |
| 代理职责 | 反向代理 + 鉴权头注入 + 请求透传 | **协议翻译**（consumer 标准请求 → 上游可接受形式）+ 模型名映射 + 下游鉴权 + 流式转发 + 并发/超时 + 日志脱敏 |
| 是否改配置 | 核心动作是改写第三方配置文件（v1 的 P0-5/6/7） | **P0 不碰任何配置文件**；仅在 L3 CLI 包装场景需读取上游启动参数（只读） |

> 一句话：**v1 是"把流量引进来"，v2 是"把能力放出去"。**

## 2. 通用化三条硬约束（含验收项）

| # | 硬约束 | 具体含义 | 验收项（可测） |
|---|---|---|---|
| G1 | **不硬编码厂商** | 主程序中不得出现任何厂商名/固定路径/固定端口作为功能分支；扫描结果只是「候选列表」，不是白名单 | ① 全仓库检索无厂商名字面量（适配器描述文件除外）；② 删除所有适配器文件后程序仍能启动并正常展示空列表与"自定义添加"入口；③ 手动指定任意未识别 exe/命令即可创建一个自定义条目 |
| G2 | **适配器 manifest 驱动、可外挂** | 每款软件的能力声明 = 一份描述文件（发现规则、端点/CLI 形态、协议类型、模型映射、鉴权方式）；新增一款软件 = 新增一份描述文件，**不改主程序、不发版** | ① 在不重新编译主程序的前提下，把一个新描述文件放入适配器目录即被识别并出现在列表；② 描述文件有 schema 校验，非法文件被拒绝且给出字段级错误；③ 描述文件损坏不影响其他适配器加载（故障隔离） |
| G3 | **可社区贡献** | 描述文件格式有公开文档与模板；支持导入/导出单个适配器；支持标注来源与维护等级 | ① 提供空白模板 + 字段说明；② 可导出单个适配器为单文件交付他人；③ 每个适配器可标注 `maintainer` / `level`（官方/社区/实验性）并在 UI 展示 |

> 三条约束的共同验收底线：**新增第二款软件的工作量 = 写一份描述文件 + 验证，不触发主程序发版。**

## 3. 上游 / 下游模型（新定位）

```
上游 Upstream（能力的提供方）
  Agent GUI 客户端 / Agent CLI / 本地推理服务
        ↑  代理按等级适配（L1 直通 / L2 协议转换 / L3 CLI 包装）
   ┌─────────────────────────────┐
   │  本地代理 (127.0.0.1:port)   │
   │  · /v1/chat/completions      │
   │  · /v1/models                │
   │  · 下游 token 鉴权            │
   │  · 模型名映射                 │
   │  · 流式转发 / 并发 / 超时      │
   └─────────────────────────────┘
        ↓  OpenAI 兼容协议（下游看到的是标准端点）
下游 Consumer（能力的使用方）
  IDE 插件 / 脚本 / 另一个 CLI / 自研程序 / 本地工作流
```

### 3.1 产品价值主张（v2）

> **把本机任意一个 agent 的模型能力，变成 `http://127.0.0.1:<port>/v1` 这样一个谁都能用的标准端点。**

### 3.2 与 v1 目标的继承与替换

| 目标 | 状态 |
|---|---|
| 发现要准（三源扫描 + exe 去重） | ✅ 继承，但**降级为"候选建议"**，不再是白名单 |
| 代理要能用 | 🔄 重新定义：下游能用标准 OpenAI 协议打通上游 |
| 改坏能兜底 | ⬇️ 降为 P2（P0 不改配置，风险自然消失） |
| **新增：分级要准** | 🆕 能判定一个 agent 是 L0/L1/L2/L3，并给出可信的可用性预期 |

## 4. 可代理性分级 L0–L3

分级 = **探测得出的建议值**，最终以 manifest 声明为准，用户可覆盖。

| 级别 | 含义 | 判定依据（→ 对应检测动作） | 用户可见提示 | 可用能力 |
|---|---|---|---|---|
| **L0** | 不可代理 | ① 该进程/该软件无任何 LISTEN 端口（→ 快照 `GetExtendedTcpTable` 按 PID 归集）；② 无 CLI 或 CLI `--help` 输出中无无头执行子命令（→ 执行一次 `--help` 并关键词匹配 `print/exec/run/prompt/-p`）；③ 存在 GUI 窗口且需人工登录交互（→ 枚举窗口 + 需登录判定） | **灰显** + 具体原因（如"仅提供图形界面，且未开放本地端口"） | 无 |
| **L1** | 端口直通 | `GET http://127.0.0.1:<port>/v1/models` 返回 200 且响应体符合 `{data:[{id:...}]}`（→ 对每个监听端口并发探测，带 2s 超时） | **绿色「可直接接入」** | chat / models / 流式，零转换 |
| **L2** | 协议适配 | 端口有 HTTP 响应（任意状态码/JSON 形态），但 `/v1/models` 不满足 L1 判定 → 需字段映射（→ 探测多候选路径 `/v1/models`、`/models`、`/api/*`，记录响应形态） | **黄色「可接入，需适配」**，并在详情页显示"上游协议片段"（截断脱敏） | 取决于 manifest 描述的转换能力；未描述的部分明确报"不支持" |
| **L3** | CLI 包装 | 无可用 HTTP 端点，但 CLI 支持非交互单次调用（读 stdin 或 argv 输出结果）且能输出流（→ 检查 `--help` 是否含 output/json/stream 相关开关） | **橙色「可用但性能有限」** + 实验性标识 | 单次调用；流式需伪造；并发受限；延迟高 |

### 4.1 分级判定必须承认的不确定性

| 情形 | 处置 |
|---|---|
| 探测超时/端口无响应 | 标记「未知」，不臆测为 L0；允许用户手动指定级别 |
| 端口活着但返回 HTML（如 Electron 静态资源服务器） | 判为 **L2 待定**（不是 L1）——**注意：这正是本机 DSH 3082 的真实情况，见附录 E2** |
| 软件已安装但未运行 | 一律先标「未就绪」，不是 L0；提示"启动该软件后再探测" |
| 用户手动覆盖级别 | 允许，但记录来源为"用户指定"并在 UI 标注 |

## 5. 消费者侧用户故事

| # | 作为 | 我希望 | 以便 | 验收要点 |
|---|---|---|---|---|
| CS-01 | 下游使用者 | 在工具里只填 baseURL 和 api key 就能用 | 不用理解上游是什么形态 | 填入 `http://127.0.0.1:<port>/v1` 后 `/v1/models` 可列出模型 |
| CS-02 | 下游使用者 | 在 UI 上直接复制现成的配置片段 | 不用记端口和路径 | 每个 consumer 类型有可复制片段（见 5.1） |
| CS-03 | 下游使用者 | 知道该填哪个 model 名，并且能一键复制 | 不会因为模型名猜错而 404 | 模型清单页每行有复制按钮；`/v1/models` 与实际可调用一致 |
| CS-04 | 下游使用者 | 上游模型 id 和我看到的名字不同也能对上 | 上游改名不影响我的配置 | 支持模型别名映射（别名 → 上游 id），UI 展示两者 |
| CS-05 | 下游使用者 | 上游不支持 tool_calls 时，得到明确报错而不是默默失败 | 能判断是我的问题还是上游不支持 | 不支持的字段返回结构化错误码 + 人类可读原因 |
| CS-06 | 下游使用者 | 流式输出能正常逐字返回 | 交互体验不退化成"等全部生成完" | SSE 逐 chunk 输出，超时可控 |
| CS-07 | 下游使用者 | 上游没启动时，代理能告诉我该去启动什么 | 不用自己排查 | 上游不可达 → 明确提示软件名 + 建议动作（启动/重探测） |
| CS-08 | 谨慎使用者 | 只有我允许的进程能用这个端点 | 防止本机其他程序或网页白用我的额度 | 未带 token 请求返回 401（见 Q8） |
| CS-09 | 下游使用者 | 看到当前代理的并发数、错误率、超时统计 | 判断瓶颈在哪 | 运行态面板含并发/错误率/P95 延迟 |

### 5.1 用户实际会复制的配置片段（以端口 8787 为例）

**通用（OpenAI SDK / 大多数工具的自定义供应商）**

```
baseURL : http://127.0.0.1:8787/v1
apiKey  : sk-local-＜首次启动时生成的本地令牌＞
model   : ＜从模型清单复制，例如 glm-5.3-flash＞
```

**环境变量方式（多数 CLI / SDK 通用）**

```
OPENAI_BASE_URL=http://127.0.0.1:8787/v1
OPENAI_API_KEY=sk-local-＜本地令牌＞
OPENAI_MODEL=＜从模型清单复制＞
```

**验证一行（用户可自行粘贴自检）**

```
curl http://127.0.0.1:8787/v1/models -H "Authorization: Bearer ＜本地令牌＞"
```

### 5.2 「该填哪个 model 名」怎么解决

| 情形 | 模型清单从哪来 | 用户可见 |
|---|---|---|
| 上游 L1 | 直接透传上游 `/v1/models` 结果 | 实时列表，标注来源=上游 |
| 上游 L2 | manifest 声明静态模型清单 + 可选从上游接口探测 | 列表标注来源=适配器声明 |
| 上游 L3 | 只能来自 manifest 静态声明 | 列表标注来源=适配器声明 + 「实验性」 |
| 上游不提供任何模型信息 | 显示"未知模型"，允许用户手填并自测 | 提供"测试该模型名"按钮，返回结果即写入清单 |

**产品要求**：模型清单页每一行必须包含「别名 / 上游真实 id / 来源 / 是否已验证」四列，并对每一行提供一键复制。

## 6. 调整后的 P0 / P1 / P2

### 6.1 P0（Must have — 单里程碑可交付）

| ID | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| P0-1 | **manifest 适配器机制** | 外挂目录 + schema 校验 + 故障隔离 + 不硬编码厂商 | 放入新描述文件即生效，无需改主程序（G2 全项） |
| P0-2 | 候选发现 + 自定义添加 | 三源扫描结果仅作候选；支持手动指定 exe/命令 + 自定义适配器 | 未识别软件可手动入库并持久化（G1 全项） |
| P0-3 | 可代理性探测（L0–L3） | 按 §4 检测动作给出建议级别 + 原因 | 4 种级别各有可复现的判定样例；未知有独立标记 |
| P0-4 | **至少 1 个真实可跑的 L1/L2 适配器样例** | 作为机制的可运行证明（选型见 Q11） | 端到端：consumer 调用 → 上游真实返回 |
| P0-5 | 本地端点 | `127.0.0.1` 上暴露 `/v1/chat/completions`、`/v1/models`，支持 SSE 流式 | 官方 OpenAI SDK 直连可用 |
| P0-6 | 模型清单 + 复制 | 别名 / 上游 id / 来源 / 已验证 四列 + 一键复制 | `/v1/models` 与实际可调用一致 |
| P0-7 | 消费者接入指引 | 内置通用片段 + 环境变量片段 + 自检 curl | 用户按指引可在 3 分钟内接通 |
| P0-8 | 健康检查 / 停止即回收 | 上游可达性、端点存活、停止后端口释放、进程清理 | 停止后端口立即释放，无残留进程；上游掉线 30s 内标红 |
| P0-9 | 下游鉴权（默认开） | 本地令牌，可在设置中关闭（决策见 Q8） | 无 token → 401；token 可重置 |
| P0-10 | 日志脱敏 | 只记元数据（时间/模型/状态码/耗时/token 计数），不记 prompt 与响应体 | 日志与配置中无明文 key、无对话内容 |
| P0-11 | 错误语义化 | 上游不支持的字段/能力 → 结构化错误码 + 人话原因 | 报错可区分「上游不支持」「上游不可达」「限流」「超时」 |

**P0 明确不做（防止范围回弹）**：❌ 多平台 ❌ 多适配器齐备 ❌ 配置改写 ❌ L3 CLI 包装 ❌ 计费/用量账单 ❌ 请求重放/录制

### 6.3 Out of Scope

| 不做 | 理由 |
|---|---|
| 云端账号 / 订阅 / 密钥托管 | 与本地工具定位冲突，承担不必要合规义务 |
| 模型路由计费、账单结算 | 商业系统范畴 |

## 7. 新增风险（v1 的 20 条之外）

| ID | 风险 | 触发条件 | 影响 | 缓解措施 | 可验收项 |
|---|---|---|---|---|---|
| N1 | 上游协议不标准 / 字段差异 | 上游不支持 `tool_calls`、`stream`、`reasoning_content`、多 system 消息、`response_format` 等字段 | 下游调用报错或静默丢功能（最坏：agent 拿到残缺上下文仍返回结果） | 能力协商表（manifest 声明支持项）+ 不支持字段返回结构化错误而非忽略 + 显式降级开关 | 对每个不支持的字段有独立错误码；错误信息含字段名与上游名 |
| N2 | 上游限流与额度耗尽 | consumer 并发高 / 上游有 QPS 或日额度限制 | 请求被限流；严重时**烧光用户付费额度且无感知** | 透传上游 429 语义 + `Retry-After` + 按 consumer 并发上限 + 用量可见 + 额度告警阈值 | 上游 429 → 下游收到 429 且带 retry-after；用量达阈值有告警 |
| N3 | GUI agent 无 API 面，只能 CDP/CLI 包装的脆弱性 | manifest 走 L3 或依赖 GUI 内部通道 | UI 改版即失效；注入通道带来稳定性与合规争议；误操作可影响用户正在用的会话 | P0 不做 L3；如做必须：显式"实验性"标识、独立进程隔离、硬超时、失败可诊断、不触碰用户已有会话 | L3 适配器带实验性标识；失败时有可读诊断；不影响用户在跑的会话 |
| N4 | consumer 兼容性长尾 | 不同 consumer 对 SSE chunk 边界、`data: [DONE]`、空行、`tool_calls` 增量拼接容忍度不同 | 某个 consumer 收不到流或解析失败，但另一个正常 → 难定位 | 输出严格对齐 OpenAI schema；提供官方 SDK / curl / 至少 3 种 consumer 的冒烟清单；错误响应保留原始上游片段（脱敏） | 3 种以上 consumer 冒烟通过；SSE 输出通过 schema 校验 |
| N5 | 上游软件升级导致适配失效 | 上游改端点路径、改端口、改协议字段、改名（v1 已实测到配置文件被改名） | 代理表面"运行中"但实际不可用 | 启动即健康检查 + 周期探测 + 失效标红并给出"适配器可能过期"提示 + manifest 版本号比对 | 上游失效后 30s 内标红并提示原因；不出现"假绿" |
| N6 | 越权：把 agent 付费额度开放给本机任意进程 | 端点无鉴权且绑 `127.0.0.1`；**浏览器中任意网页的 JS 也能请求 localhost** | 本机恶意脚本、甚至恶意网页白用额度；若误绑 `0.0.0.0` 则扩散到局域网 | 强制默认 bearer token（随机生成、展示一次、可重置）+ **严格 CORS（不返回通配）** + 绑定地址锁 127.0.0.1 + 请求来源日志 | 无 token → 401；跨域预检被拒；绑 `0.0.0.0` 需二次确认；日志可按 consumer 追溯 |
| N7 | 单实例阻塞放大 | 上游 L3 或串行上游，一个慢请求拖住全部 | 下游整体超时 | 每请求硬超时 + 并发上限 + 队列溢出快速失败（503 而非挂住） | 慢请求不阻塞其他请求；超时返回结构化 504 |

## 附录 E：本机证据样本（**仅作证据，不进入范围定义**）

| # | 实测事实 | 对设计的验证意义 |
|---|---|---|
| E1 | **全机未发现现成的 OpenAI 兼容本地端点**：Ollama(11434)、LM Studio(1234) 端口无响应；探测的多个端口无一满足 `/v1/models` | 证明 L1 是「需要上游主动开启才存在」的稀缺状态 → 分级与"未就绪"状态必须存在，不能假设上游天生可用 |
